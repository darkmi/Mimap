# Mimap（KityMinder Editor）整体架构分析与升级方案

> 基线：v1.0.67，2019 年代码，2026-10 仍可在 Node 20 下构建运行。
> 本文档为现状分析 + 分阶段升级路线图，供决策与排期使用。

---

## 一、现状架构分析

### 1.1 技术栈全景

```
┌─────────────────────────────────────────────────────────────┐
│  示例/宿主  index.html（AngularJS 引导 + SeaJS 加载编辑器）      │
├─────────────────────────────────────────────────────────────┤
│  UI 层  ui/（~4500 行 JS + 591 行 HTML 模板）                  │
│  AngularJS 1.3.15 + jQuery 2.1.4 + Bootstrap 3.3.4           │
│  angular-bootstrap 0.12 / color-picker / CodeMirror 4.8      │
│  27 个 directive + 9 个 service + 3 个 dialog + 2 个 filter   │
├─────────────────────────────────────────────────────────────┤
│  编辑器运行时  src/（~3300 行，SeaJS CMD 模块 × 25）             │
│  KMEditor：组装 15 个 runtime                                  │
│  fsm(状态机) receiver/hotbox/input/clipboard/drag/history/    │
│  jumping/priority/progress/node/container/minder             │
├─────────────────────────────────────────────────────────────┤
│  脑图内核  kityminder-core 1.4.50（npm）                       │
│  数据模型 / 命令系统 / 布局模板 / 主题 / 导入导出协议             │
├─────────────────────────────────────────────────────────────┤
│  矢量图形库  kity 2.0.5（SVG 渲染，window.kity 全局）           │
├─────────────────────────────────────────────────────────────┤
│  构建  Grunt 0.4.5 + Bower + grunt-module-dependence(CMD 合并) │
│  ngAnnotate → concat → uglify2 → less → cssmin               │
│  后端  server/imageUpload.php（仅图片上传示例，非必需）          │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 架构的优点（升级中要保住的资产）

1. **分层清晰**：内核（kityminder-core）/ 编辑器运行时（src）/ UI（ui）三层解耦。
   `src/` 层完全不依赖 Angular，只依赖 DOM 与 `window.kityminder` 全局。
2. **内核是核心资产**：kityminder-core 的数据模型、命令系统（queryCommandState/Value）、
   6 种布局模板、20+ 主题、json/text/markdown/svg/png 导入导出协议，都是成熟且难重写的部分。
3. **UI 桥接模式简单**：`commandBinder` 服务把 `minder.on('interactchange')` 转成 scope 状态，
   27 个 directive 基本都是"读命令状态 → 调 execCommand"的薄壳。
4. **代码量小**：全库（不含依赖）约 5100 行 JS + 591 行模板 + 约 1300 行 less，
   UI 层整体重写完全可控。

## 二、升级方案比选

| 方案 | 内容 | 成本 | 结论 |
|------|------|------|------|
| A. 原地小升级 | AngularJS 1.3→1.8.3、jQuery 3、锁定 marked 版本，其余不动 | 1 周内 | **仅作止血**，框架 EOL 问题无解 |
| B. 内核保留 + UI 重写（推荐） | 保留 kityminder-core + src 运行时（改造 ESM/TS），UI 层用 Vue 3 + TS + Vite 重写 | 4~6 周 | 治本，投入产出比最优 |
| C. 整体换引擎 | 弃 kityminder，换现代脑图库（如 SimpleMindMap 等） | 8 周+，数据/模板/主题/协议全部重做 | 除非有 kity 渲染层无法满足的需求，否则不推荐 |

**推荐 B**，框架选 **Vue 3** 而非 React/Angular 的理由：
- 模板语法与 AngularJS 指令相似度最高（`ng-if/ng-repeat/ng-model` ≈ `v-if/v-for/v-model`），
  27 个 directive 的 HTML 模板可近似的"语法替换"式迁移，心智成本最低；
- 中文社区生态成熟（后续维护者好找），配合 Pinia/Vite 工具链一致。

## 三、分阶段路线图（推荐 B 方案）

> **进度（2026-10-29）：Phase 0、1、2 已完成并通过浏览器全功能回归。Phase 3 部分完成（TS 类型 + 单元测试 + legacy 修复）。随后已完成 Angular 全量下线：删除 `ui/`、`legacy.html`、`app.js`/`main.js` 及 angular/angular-ui-bootstrap/jquery 等依赖，仅保留 Vue 3 UI。CI/Playwright 全量回归确认/fork 待续。**

### Phase 0 —— 工程基础设施先行（不动业务代码，2~3 人日）【✅ 已完成】

目标：把"包管理、模块体系、构建"三件套换成现代链路，为后续一切工作铺路。

1. **Bower → npm**：9 个 bower 依赖逐一找 npm 等价物（bootstrap、jquery、angular、
   codemirror、marked、hotbox、json-diff、seajs（将移除）、kity）；删除 `bower.json`/`.bowerrc`，
   `index.html` 引用路径改为 `node_modules` 或构建产物。
2. **SeaJS CMD → ESM**：25 个 `define(function(require){})` 模块形态高度规则，
   写脚本批量转换（`require('./x')` → `import`，`module.exports` → `export default`），
   删除 `expose-editor.js` 闭包包装与 `grunt-module-dependence` 合并逻辑。
3. **Grunt → Vite**：dev（HMR 替代 browser-sync+watch）、build（ESBuild/Rollup 替代
   concat+uglify）、`less` 保留或一次性转 Scss。删除 8 个 grunt 插件依赖。
4. 建立基线：git 打 tag、Node LTS + corepack/pnpm、`.editorconfig`、ESLint + Prettier。

验收：`pnpm dev` HMR 可用，`pnpm build` 产物功能与当前 dist 一致（人工回归 + 截图对比）。

### Phase 1 —— 依赖安全止血（1~2 人日，可独立发布一个过渡版本）【✅ 已完成】

在 Phase 0 基础上，不做重写、先把 CVE 消掉：

1. angular 1.3.15 → **1.8.3**（终版，含累计安全修复；ngAnnotate 相关配置同步清理）
2. jquery 2.1.4 → **3.7.1**（同时消除 Bootstrap 3 的 jQuery 老接口告警）
3. marked 锁定最新版 + 引入 **DOMPurify**（备注/富文本预览统一过消毒）
4. codemirror 4.8 → **5.65.x**（API 兼容面大、迁移成本低；6 留给 Phase 3）
5. 移除 baidu 内网域名白名单硬编码，改为可配置

验收：全量功能回归 + 依赖扫描（`pnpm audit`）无 high 以上漏洞。

### Phase 2 —— UI 层 Vue 3 重写（3~4 周，核心工程）【✅ 已完成】

原则：**逐组件迁移、新旧并存、随时可发布**。

1. **骨架**：Vue 3 + TypeScript + `<script setup>` + Pinia + Vite；样式系统在
   "Bootstrap 5" 与 "Tailwind" 中二选一（建议 Tailwind：脑图工具 UI 面积小、定制多，无组件库包袱更轻）。
2. **状态与事件桥**（替代 $scope/commandBinder）：
   - `useMinder()` composable：持有 editor/minder 实例，替代 `window.editor/minder` 全局；
   - `useCommand(name)` composable：内部监听 `interactchange`（rAF 节流）暴露
     `disabled/value/exec()`，对应现在 27 个 directive 的公共模式；
   - Pinia store：选区、标签资源、撤销弹窗、语言包。
3. **组件映射表**（27 directive → 组件，工作量基准）：

   | Angular directive | Vue 3 组件 | 备注 |
   |---|---|---|
   | kityminderEditor / kityminderViewer | `<KmEditor>` / `<KmViewer>` | 挂载 src 运行时，`onInit` 改 emit |
   | topTab | `<KmTabBar>` | 思路/外观/视图三页签 |
   | undoRedo / operation / appendNode / arrange | `<KmToolbar>` 子组件 | 全部基于 useCommand |
   | priorityEditor / progressEditor / resourceEditor | `<KmPriority>` 等 | 图标面板 |
   | fontOperator / styleOperator / colorPanel | `<KmFont>` / `<KmStyle>` | color-picker 替换为自绘取色板 |
   | templateList / themeList / layout / expandLevel / selectAll | `<KmAppearance>` 系列 | 列表读 minder 数据 |
   | noteEditor / notePreviewer | `<KmNote>` | CodeMirror 5 封装 + marked+DOMPurify |
   | hyperlink / image / imExportNode（dialog） | `<KmDialog*>` | 自研轻量弹窗或 headless 组件 |
   | searchBox / searchBtn / navigator | `<KmSearch>` / `<KmNavigator>` | 缩略图 canvas 逻辑照搬 |

4. **并存策略**：构建同时产出 `mimap-editor.js`（新，Web Component 或 Vue 插件两种发布形态）
   与旧 `kityminder.editor.js`，`index.html`（新 demo）与 `legacy/`（旧 demo）并行，
   对比验收后切换、下线旧 UI。
5. 国际化：现仅有 `lang.zh-cn.service`，抽成 json + `vue-i18n`，顺手补 en。

验收：27 个功能点对照清单逐一过（附录 A），Playwright 截图对比新旧 UI。

### Phase 3 —— 深度现代化与质量体系（持续迭代）【🔶 部分完成】

1. **src 运行时 TS 化**：fsm/receiver 等补类型；为 kityminder-core 编写 `.d.ts`
   （上游无类型，自写声明文件随包发布）。
2. **fork 自持 kityminder-core / kity**：修 bug、升依赖、发私有 npm 包（`@mimap/core`）。
3. **测试网**：Vitest 单测（命令/协议/jsondiff 等纯逻辑）+ Playwright E2E
   （新建/编辑/折叠/导入导出/撤销等核心流）。
4. **CI/CD**：GitHub Actions——lint + typecheck + test + build + 发布 npm。
5. 可选项：CodeMirror 6、图片上传 PHP 示例换 Node 中间件、`relations.png` 等文档更新。

## 附录 C：Phase 2 实施记录（2026-10-29）

### 架构决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 状态管理 | 单 `shallowReactive` store（不用 Pinia） | 编辑器实例是 kity 复杂对象，shallowReactive 避免深度代理；Pinia 对本场景过重 |
| 交互响应 | `interactVersion` 版本号 + `cmdState/cmdExec` helper | 替代 `commandBinder.bind` + `$scope.$apply` 模式；rAF 节流防止 `interactchange` 高频触发卡顿 |
| 下拉菜单 | 自定义 `kmDropdown` 指令 + Bootstrap 3 `.open` 类 | 不引入额外 UI 库；`.open` 类由 Bootstrap CSS 接管样式 |
| 弹窗 | 自定义 `KmModal` + Teleport + Bootstrap `.modal-*` 类 | 替代 `$uibModal`；Esc 关闭、mask 点击关闭 |
| 取色器 | 自定义 `KmColorPicker`（10×10 色板 + localStorage 最近使用） | 替代 fex color-picker（Angular 指令依赖） |
| 样式复用 | 保持原 DOM 结构与 class 命名 | 现有 `editor.less` 样式直接生效，零样式重写 |
| 双轨并存 | `index.html`（Vue）+ `legacy.html`（Angular） | 多页 Vite 构建，随时对比/回退 |

### 组件映射（27 directive → 18 Vue 组件 + 4 个辅助模块）

| 类别 | Angular | Vue |
|------|---------|-----|
| 容器 | kityminderEditor | `KmEditor.vue`（挂载 src 运行时） |
| 页签 | topTab | `KmTabBar.vue`（3 页签 + 18 子组件） |
| 工具栏 | undoRedo / appendNode / arrange / operation | `KmUndoRedo` / `KmAppendNode` / `KmArrange` / `KmOperation` |
